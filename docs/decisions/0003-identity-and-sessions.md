# ADR-0003: собственная модель Identity и серверные сессии

- Статус: принято
- Дата: 2026-07-28

## Контекст

Основным способом входа Академии должен быть Telegram. В дальнейшем ученику
может понадобиться привязать электронную почту или телефон к тому же аккаунту.
Платежи, подписки и прогресс должны ссылаться на стабильный внутренний
идентификатор, а не на Telegram ID или адрес почты.

## Решение

Хранить ученика в `identity_users`, а подтверждённые способы входа — отдельно в
`identity_methods`. Один пользователь может иметь несколько методов:
`telegram`, `email` и `phone`.

После подтверждения внешней идентичности сервер создаёт случайный 256-битный
session-токен. Токен передаётся браузеру в `HttpOnly`, `SameSite=Lax` cookie, а
в PostgreSQL хранится только его SHA-256 хэш. Production-cookie дополнительно
имеет атрибут `Secure` и префикс `__Host-`.

Первый production-способ входа — Telegram OpenID Connect с Authorization Code
Flow. Для каждого входа сервер создаёт случайные `state`, `nonce` и
PKCE `code_verifier`, связывает их с маршрутом возврата и версией согласия в
подписанном `HttpOnly` cookie. Callback принимается только из того браузерного
сценария, который начал вход. Сервер обменивает одноразовый код с
`code_verifier`, проверяет `state`, `nonce`, издателя, аудиторию, срок действия
и цифровую подпись ID Token по JWKS Telegram, затем удаляет cookie.
Каноническим внешним идентификатором служит проверенный OIDC `sub` в
пространстве метода `telegram`. Провайдерский Telegram `id` хранится только в
metadata для диагностики и не связывает платежи или доступы. Вход по
электронной почте использует одноразовую ссылку; до подключения отправщика
писем он доступен только в локальном demo-режиме.

## Правила

1. Billing, Courses и Access используют только `identity_users.id`.
2. Авторизация повторно проверяется в каждом защищённом Route Handler или
   Server Component.
3. Redirect или наличие cookie без действующей записи сессии не дают доступ.
4. Demo-вход физически недоступен при `NODE_ENV=production`.
5. Ссылка входа по почте одноразовая и действует 15 минут.
6. Выход отзывает серверную сессию, а не только удаляет cookie.
7. Согласие на обработку данных записывается с версией документа и источником.
8. Telegram callback без свежих browser-bound `state`, `nonce` и PKCE
   `code_verifier` не создаёт сессию.
9. Изменение Telegram `username`, имени или фотографии не меняет связь с
   `identity_users`: она определяется только проверенным OIDC `sub`.

## Последствия

- Telegram, email и телефон можно связать с одним учеником;
- потеря дампа хэшей сессий не раскрывает действующие cookie-токены;
- не требуется внешний Identity SaaS;
- нужно самостоятельно сопровождать Telegram OpenID Connect, отправку писем и
  очистку истёкших сессий;
- перед production необходимо зарегистрировать точный callback
  `https://academy.abrikosoff.com/api/auth/telegram/callback` в BotFather и
  установить OIDC Client ID и Client Secret на сервере.
