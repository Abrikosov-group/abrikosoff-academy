# Локальная функциональная проверка ручного доступа

Инструкция проверяет ACA-0007 локально и не меняет staging или production.

## Профиль включённой выдачи

1. Подготовить тестовую базу командой `npm run test:db:prepare`.
2. Запустить приложение с `EFFECTIVE_ACCESS_MODE=v2` и
   `MANUAL_ACCESS_GRANTING_ENABLED=true`.
3. Войти владельцем, открыть `/admin/students/{userId}` и выдать ученику без
   оплаты ручной период с отдельной причиной.
4. Подтвердить ручной источник в карточке и `/admin/access`, отсутствие
   созданного заказа или платежа, доступ ученика в `/dashboard/courses` и к
   защищённому уроку.
5. Отозвать конкретный ручной грант через UI и подтвердить красное сообщение,
   сохранённую историю и новое эффективное состояние.
6. Повторить выдачу пересекающимся периодом и подтвердить предупреждение о
   пересечении без блокировки команды.

Автоматизированный эквивалент этого пути выполняет
`tests/e2e/manual-access-enabled.spec.ts`.

## Профиль выключенной выдачи

Отдельный Playwright-процесс запускается с
`MANUAL_ACCESS_GRANTING_ENABLED=false`. До старта Next.js скрипт
`scripts/start-manual-access-disabled-e2e.mjs` создаёт изолированного владельца,
ученика и действующий ручной грант в тестовой базе.

Проверка подтверждает закрытую форму и стабильный `409` нового POST, затем
штатно отзывает заранее созданный грант и подтверждает закрытие доступа,
сохранённую историю и отсутствие платежа. Автоматизированный сценарий:
`tests/e2e/manual-access-disabled.spec.ts`.

Оба профиля запускаются одной командой:

```bash
npm run test:e2e
```

## Последняя локальная проверка

31 августа 2026 года оба профиля ACA-0007 выполнены на ветке
`codex/recurring-subscriptions`:

- включённая выдача: поиск и выбор ученика в `/admin/access`, две
  пересекающиеся выдачи, доступ к кабинету и защищённому уроку, отзыв одного
  гранта с сохранением доступа за счёт второго, мобильный viewport и отсутствие
  Billing-записей;
- выключенная выдача: закрытая форма, прямой POST нового ключа с HTTP `409`,
  просмотр и отзыв существующего гранта, сохранённая история и отсутствие
  Billing-записей.

Проверка относится только к локальной тестовой базе. Staging и production не
изменялись.
