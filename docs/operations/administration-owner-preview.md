# Ограниченный production-preview Administration

Инструкция включает владельцу только статический защитный фундамент
`https://academy.abrikosoff.com/admin`. Решение и границы описаны в
[ADR-0007](../decisions/0007-production-owner-preview.md).

## Что разрешено

- вход в `/admin` пользователю с активной ролью `owner`;
- повторное подтверждение административной сессии через Telegram;
- просмотр статической страницы защитного фундамента;
- переход между `/admin` и личным кабинетом;
- выход из учётной записи.

Статистика, ученики, доступы, платежи, курсы, аудит, роли и любые изменения
данных в preview не разрешены.

## Условия включения

1. Развёрнут образ с поддержкой `ADMINISTRATION_MODE`.
2. `APP_BASE_URL` точно равен `https://academy.abrikosoff.com`.
3. Demo-вход выключен.
4. Первый владелец уже имеет:
   - действующий production-аккаунт с Telegram OIDC;
   - активную роль `owner`;
   - проверенный обычный вход в личный кабинет.
5. Текущая конфигурация `/opt/academy/shared/.env` сохранена в закрытую
   root-owned резервную копию без вывода содержимого в терминал или логи.
6. Подготовлен быстрый откат `ADMINISTRATION_ENABLED=false`.

## Включение

В `/opt/academy/shared/.env` устанавливаются:

```dotenv
ADMINISTRATION_ENABLED=true
ADMINISTRATION_MODE=owner_preview
```

После изменения запускается штатный `workflow_dispatch` файла
`.github/workflows/release.yml` для текущего принятого `main`. Ручная сборка
или копирование исходников на production-сервер не выполняются.

## Проверка

После успешного release workflow:

1. `/api/health` возвращает `status=ok` и SHA выпущенного коммита.
2. Неавторизованный запрос к `/admin` переводит на штатный вход.
3. Обычный пользователь без роли `owner` получает отказ.
4. Владелец после Telegram-подтверждения видит только статический фундамент.
5. Переходы «Личный кабинет» и «Администрирование» сохраняют общую
   пользовательскую сессию.
6. Выход завершает пользовательскую и административную сессию.
7. В логах нет токенов, cookies, Telegram identifier или других персональных
   данных.

Негативные проверки `operational` на production-origin и предметных
разрешений preview выполняются unit- и integration-тестами, а не изменением
боевой конфигурации.

## Откат

1. Установить в `/opt/academy/shared/.env`:

   ```dotenv
   ADMINISTRATION_ENABLED=false
   ADMINISTRATION_MODE=owner_preview
   ```

2. Повторно запустить штатный production release для принятого SHA.
3. Убедиться, что `/api/health` исправен, а `/admin` снова возвращает `404`.
4. Сохранить время, SHA и причину отката в журнале выпуска без секретов и
   персональных данных.

Полный `operational`-режим этой инструкцией не включается.
